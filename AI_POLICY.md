# AI usage disclosure & policy

## Disclosure for this repository

The initial version of this repository - the app manifest, container
build, shell/Python code (Chromium/Xvfb/ffmpeg/mediamtx orchestration,
the ONVIF/WS-Discovery service, the ingress web panel) and documentation
(README, DOCS, this policy, NOTICE, SECURITY, CONTRIBUTING) - was
generated by an AI coding agent (Claude, by Anthropic, via Claude Code)
at the request of and under the direction of the repository owner,
Marcel Hoess.

Concretely, this means:

- Requirements, scope and design decisions (e.g. the ONVIF/RTSP
  approach, host networking, the credential model, the loopback-only
  ingress panel) were specified by the repository owner and implemented
  by the AI agent.
- The agent researched current Home Assistant App/add-on conventions,
  third-party licenses referenced in [NOTICE.md](./NOTICE.md), and the
  relevant protocol specifications (ONVIF, WS-Discovery, WS-Security)
  while producing this repository, and cites its sources there.
- **Nothing here has been independently tested against a real Home
  Assistant instance, UniFi Protect deployment, or a range of ONVIF
  clients as part of producing this repository.** Treat this as a
  functional starting point, not a guarantee - review the code,
  especially [SECURITY.md](./SECURITY.md), and test in your own
  environment (particularly the authentication paths) before relying on
  it, and before exposing any port on your network.
- Ongoing changes may be made by the repository owner directly, by other
  human contributors, or with further AI assistance disclosed the same
  way in commit messages and pull requests.

## Policy for contributions

This project welcomes AI-assisted contributions, on these terms:

- **You are responsible for what you submit.** If you use an AI tool to
  help write code, tests, or documentation, you must read, understand,
  and be able to explain every change in your pull request. Submitting
  unreviewed AI output wastes maintainer time and will not be merged.
- **Autonomous agents opening pull requests or issues unattended are not
  accepted.** A human must review and take responsibility for the
  submission before it is opened.
- **Disclose significant AI assistance** in your PR description (a short
  note is enough, e.g. "drafted with AI assistance, reviewed and tested
  by me").
- **Security- and auth-relevant changes** (the ONVIF/WS-Security code,
  credential handling, network exposure, the Dockerfile's privilege
  model) get extra scrutiny regardless of how they were produced - AI
  assistance doesn't change the review bar there, if anything it raises
  it.
- Using AI to improve grammar, clarity, or translate a contribution
  written by a non-native English speaker is always fine; the technical
  substance must still be your own understanding.

## Why disclose this at all

Camera/NVR integrations touch authentication, credentials and network
exposure directly. We'd rather be explicit about how this code came to
exist than have users assume a level of manual scrutiny that hasn't
happened yet - see [SECURITY.md](./SECURITY.md) for the specific
trade-offs this app makes and what to verify yourself.
